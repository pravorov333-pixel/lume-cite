# LumeVisuals Bot

Telegram-бот: бесплатная подписка за задания, продажа ключей (крипта/Stars),
поддержка, соцсети. Данные хранятся в том же проекте Supabase, что и у сайта.

## Настройка

### 1. Supabase

Если ещё не выполнял `supabase/schema.sql` из корня репозитория — сделай это
сначала (там таблицы сайта: `profiles`, `listings` и т.д.).

Затем в том же проекте (SQL Editor → New query) выполни
`bot/src/db/schema.sql` — он добавит таблицы бота: `bot_users`,
`free_task_submissions`, `bot_orders`.

### 2. Переменные окружения

```bash
cd bot
cp .env.example .env
```

Заполни `.env`:

- `BOT_TOKEN` — токен от @BotFather.
- `ADMIN_CHAT_ID` — твой числовой Telegram ID (не @username). Узнать можно
  у @userinfobot: напиши ему `/start`, он покажет твой ID.
- `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` — те же, что у сайта, но
  **service_role** ключ (Project Settings → API), не `anon`. Это секрет,
  бэкенд обходит RLS этим ключом — никогда не клади его в браузер/сайт.
- Остальное (каналы, кошельки, цены, сроки, курс Stars) — уже проставлено
  из твоего ТЗ, поменяй при необходимости.

### 3. Запуск

```bash
npm install
npm start
```

Бот подключается к Telegram через long polling — просто держи процесс
запущенным (на своём ПК, VPS, Railway/Render/systemd и т.п.). Если процесс
не запущен — бот не отвечает, это нормально для long polling.

⚠️ Токен, который ты прислал в чат, уже был "засвечен" в переписке — после
первого успешного теста рекомендую перевыпустить его через
@BotFather → `/revoke` → `/token`, и обновить `.env`.

## Как это работает

### Бесплатная подписка

1. Юзер жмёт «🎁 Бесплатная подписка» → бот показывает 2 канала и кнопку
   «Я подписался, проверить» → бот вызывает `getChatMember` для обоих
   каналов. **Бот должен быть добавлен в оба канала** (не обязательно
   админом, но должен состоять в них/иметь к ним доступ), иначе проверка
   всегда будет возвращать «не подписан».
2. После успешной проверки — выбор формата видео (быстрое, 14 дней, или
   полный обзор, 90 дней). Тексты заданий с условиями зашиты в
   `src/handlers/freeSub.js`.
3. В любой момент юзер жмёт «✅ Я выполнил задания» на главном экране,
   выбирает категорию (Обзор/Видео) и присылает скриншоты. Бот пересылает
   их тебе (`ADMIN_CHAT_ID`) с кнопками «Одобрить/Отклонить».
4. При одобрении бот сам продлевает подписку пользователю на нужное число
   дней (14/90 — настраивается в `.env`) и присылает ему ключ.

### Покупка ключа

1. Выбор срока (30 дней / 90 дней / навсегда) → выбор способа оплаты.
2. **TON / USDT / USDC** — бот показывает адрес и сумму, ждёт от юзера
   хэш транзакции (TXID), пересылает тебе на проверку с кнопками
   «Одобрить/Отклонить». Ты сверяешь TXID в эксплорере (tonscan.org для
   TON, etherscan.io для ERC20) и подтверждаешь вручную.
3. **Telegram Stars** — оплата полностью автоматическая через нативный
   Telegram Payments (валюта `XTR`). Курс звёзд к доллару Telegram не
   публикует официально — используется значение `STARS_PER_USD` из
   `.env` (по умолчанию 75, т.е. ≈$0.013/звезда). Меняй эту цифру, если
   Telegram изменит свои цены на звёзды.
4. **NFT / «Оплатить другим способом»** — бот просто присылает контакт
   поддержки и просит написать менеджеру напрямую; ключ в этом случае
   выдаётся вручную (например, командой в Supabase или через будущую
   admin-команду).

### Поддержка / соцсети

Статичные кнопки — контакт из `SUPPORT_USERNAME` и ссылки
`TELEGRAM_CHANNEL_URL` / `TIKTOK_URL`.

### Проверка своей подписки

Команда `/status` — показывает лицензионный ключ и до какой даты активна
бесплатная/платная подписка.

## Известные ограничения MVP

- Хранение состояния диалога (сцены Telegraf) — в памяти процесса. Если
  бот перезапустится посреди заполнения формы (юзер как раз шлёт скрины
  или TXID) — придётся начать заново. Все уже сохранённые заявки/заказы
  в Supabase не теряются.
- Крипто-платежи подтверждаются вручную (см. выше) — это осознанный
  выбор, чтобы не тащить сторонние API-ключи блокчейн-эксплореров.
- Лицензионный ключ генерируется и хранится у нас в Supabase, но сам
  клиент LumeVisuals (десктопное приложение) должен уметь проверять этот
  ключ через свой собственный API — это отдельная задача, не входящая в
  этот репозиторий.
